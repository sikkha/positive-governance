# Level 1.2b Preregistration — Section 14

This document is the human-readable companion to the frozen, hashed
manifest generated by `experiments/level12b_stage_i_preregistration_
manifest.py` and stored at `outputs/level12b_stage_i_preregistration_
manifest/manifest.json` (hash in the sibling `manifest_hash.txt`:
`f5bd19df912c0653b97d83f98a4685bb6020fc18b33092e2b2e1ecf11c319b77`).
Every commitment below was fixed and frozen BEFORE Work Package J's
main discovery pipeline (Section 15) ran on real data —
`load_and_verify_manifest()` is called at the start of every
subsequent Work Package script and raises `ValueError` if the on-disk
manifest's content no longer matches its recorded hash.

## What is frozen, and where each field's value actually comes from

**Assembly, not invention.** The manifest imports every field LIVE
from the module/script that already owns it, so it can never silently
drift from the code/artifacts it describes:

- **Feasibility-ratio definitions** — from Work Package B's
  `observer/feasibility_ratios.py`.
- **Ecological bounds/strata** — from Work Package E's own already-
  frozen `design.json`, cross-checked against its own stored hash
  (stratum cut points read directly from disk, never hand-copied).
- **Institutional bounds** — from Work Package D's `PARAMETER_SPACE`
  tuple.
- **IC families** — from Work Package E's own two named families.
- **Run arithmetic** — every Work Package's own preferred/hard-minimum
  figures (see below), imported from each Work Package's own design
  script.
- **Burn-in windows** — from Work Package G's `BURN_IN_SENSITIVITY_
  DEFINITIONS`.
- **Feature dictionary** — from Work Package F's `PHENOTYPE_FEATURE_
  AUDIT`.
- **Missing-data rules** — from `observer/phenotype_discovery.py`'s
  `MISSINGNESS_STRATEGIES`.
- **Recurrence criteria** — from Work Package H's already-frozen
  `recurrence_spec.json`, likewise read and hash-checked, not
  hand-copied.
- **Clustering algorithms/k-range/model-selection metrics** — from
  `phenotype_discovery.py`'s `CANDIDATE_METHODS`, `DEFAULT_K_RANGE`.

**Two fields had no existing home and were frozen here for the first
time, BEFORE their own Work Packages executed:**

- **Confirmation rules** (`CONFIRMATION_RULES`) — Section 17's
  preferred `24×8×2=384` / hard-minimum `18×6×2=216` run arithmetic,
  the disjoint-fresh-seed policy, and the `null_replication_rule`
  ("if Section 16 discovery supports no candidates, confirmation
  replicates the null result rather than manufacturing a candidate to
  test") — the rule Work Package L's own continuum-verdict judgment
  call directly applies (see `docs/level1.2b_discovery_methods.md` §6).
- **Scale-robustness grid** (`SCALE_ROBUSTNESS_GRID`) — Section 18's 2
  population sizes × 2 patch counts × 2 network-modularity levels × 4
  seeds = 32 runs/candidate, with `scale_invariance_required: False`
  stated explicitly.

**Stop conditions** (six, 1.2b-specific — distinct from, and not
superseding, Level 1.2's own Section 20 conditions) and **compute-
budget decisions** (Work Package E's full-preferred-design run,
Work Package G's disclosed 12-seed-run validation subset, and the
standing policy for future Work Packages' own scope choices) were also
written fresh, since no such document previously existed for 1.2b.

**Frozen artifacts are never retroactively edited.** Work Packages C
through H's own `design.json`/`recurrence_spec.json` files were
already hashed under each Work Package's own established convention
before this manifest existed; the manifest embeds their hashes
(traceable provenance) rather than rewriting them.

## Explicit run-count arithmetic (committed before any outcome was seen)

- Feasibility map (Work Package C): 30 ecological points × 4 seeds =
  120 runs. **Achieved: 120/120, 0 failures.**
- Main discovery (Work Package E), preferred: 48 joint points × 6
  seeds × 2 IC families = 576 runs; hard minimum: 36 × 4 × 2 = 288
  runs. Below 288 is a stop condition (Section 27.5), not a number to
  negotiate down from after seeing partial results. **Achieved:
  576/576, 0 failures — the preferred target was met, not just the
  hard minimum.**
- Confirmation (Section 17), preferred: 24 × 8 × 2 = 384 runs; hard
  minimum: 18 × 6 × 2 = 216 runs. Below 216 is a stop condition
  (Section 27.6). **Achieved: 384/384, 0 failures.**
- Scaling robustness (Section 18): 2 population sizes × 2 patch counts
  × 2 network-modularity levels × 4 seeds = 32 runs minimum.
  **Achieved: 32/32, 0 failures.**
- Section 19 causal decomposition: matched-seed, mechanism-substream
  pairs, 13 preregistered factors, not an exhaustive factorial.
  **Achieved: 13/13 factors, 208/208 runs, 0 failures.**

Every one of these commitments was met or exceeded — none required
invoking a stop condition to reduce scope. This is disclosed
explicitly (per Level 1.2's own established precedent, see
`docs/level1.2_preregistration.md`'s "Where sample-size commitments
were interpreted" section) rather than left for a reader to verify
independently.

## Verification

```
python3 -c "from experiments.level12b_stage_i_preregistration_manifest import load_and_verify_manifest; print(load_and_verify_manifest())"
```

recomputes the SHA-256 over the on-disk manifest's canonical JSON and
compares it against the stored hash file, raising on any mismatch.
`tests/test_level12b_preregistration_manifest.py` (17 tests) covers
completeness (all 15 Section-14 fields present, versioned,
deterministic), values imported-not-hand-copied, confirmation-rule and
scale-grid arithmetic matching the task descriptions exactly, stop-
conditions/compute-budget content checks, hashing (determinism, JSON-
serializability, save/load/verify roundtrip, tamper detection), and
verification of the actual saved manifest against its own hash.

## The null-replication rule and its actual application

Work Package K's own Section 16 discovery verdict was `continuum`, not
`multi_config` — no discrete candidates to name. This manifest's own
`null_replication_rule`, frozen before that result was known, was
applied to that outcome by Work Package L exactly as if discovery had
supported zero candidates: no discrete candidate was named, bounded
with uncertainty ranges, or given an expected direction anywhere in
Work Package L's confirmation registry. Confirmation instead
stress-tested the one concrete diagnostic object Section 16 produced
(the headline_k=4 partition) for out-of-sample recurrence — see
`docs/level1.2b_discovery_methods.md` §6 for the full account and
`docs/level1.2b_scientific_note.md` for what it found.

## Stop conditions honored

No Work Package this milestone invoked a stop condition to reduce
scope below a committed figure. The one genuine mid-milestone
correction — Work Package A's short-scale ledger validation being
insufficient at production scale, discovered while preparing Work
Package E — was not a stop condition under Section 27; it was resolved
by fixing the underlying bugs (see `docs/level1.2b_ecological_
accounting.md` §2) before Work Package E's real run began, not by
reducing that run's own committed scope. The "recalibration" stop
condition (Section 19: "do not recalibrate main discovery results
afterward") was honored directly — Work Package N's causal-ablation
findings were not fed back into Work Package E's design, Work Package
I's manifest, or any other already-frozen artifact.
